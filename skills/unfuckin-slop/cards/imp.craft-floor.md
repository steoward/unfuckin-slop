# Check the built surface

Walk the primary task at a narrow and a wide shipped size, using realistic content. Record the route, state and visible outcome for each defect.

- **Hierarchy and spacing.** Identify the primary action and the information needed before it. Check grouping, headings and alignment with a short and a long label. Let dense tools, reading surfaces and campaign pages use different measures.
- **Contrast and focus.** Check foreground against the actual rendered background, including imagery or overlays. Aim for at least 4.5:1 for ordinary text and 3:1 for large text. Tab through the task and confirm the focused control stays visible. Prefer platform scrollbars and selection behavior unless custom styling serves a clear purpose.
- **States and recovery.** Exercise the states the feature can reach. Try an empty collection, a failed request or an interrupted gesture as relevant. Check usable feedback, recovery and preservation of user input.
- **Motion and depth.** Observe the interaction during rapid reversal and with reduced motion enabled. Keep content usable when decorative animation, transparency or shadows are absent. Inspect expensive effects on the target device when performance matters.
- **Copy and coverage.** Use the product's vocabulary and verify every required action reaches the intended result. Carry real long strings and localized values through the layout.

Run the linter over changed web files. Record which checks came from source inspection, rendering or interaction. Where only a screenshot exists, leave runtime behavior unverified.
